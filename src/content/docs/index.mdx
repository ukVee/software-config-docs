A **garden** is the set of files that describe a machine — how it's configured,
what's installed, why a choice was made, what broke and how it got fixed.
soft-fig treats that as one first-class object: a **memory garden**, a
**dotfile manager**, an **encryption-at-rest store**, and a **version control
system**, sharing one config and one CLI instead of four tools stitched
together. The garden is the product; everything else soft-fig ships — Growlight
included — exists to serve it.

:::caution[Single-author work in progress]
soft-fig is a single-author work in progress, not a released tool. The engine,
the Keeper surfaces (CLI, MCP, TUI), the static deploy spine, read-only
cross-device sync, and the Growlight work loop are built and self-hosting;
template rendering, a general GUI, and packaging are not. See
[where the code is today](internals/status/). The
[code repository](https://github.com/ukVee/software-config-garden) remains the
source of truth.
:::
